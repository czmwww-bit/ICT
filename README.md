# 银龄办事通 · 组内开发说明

**暂定题目：银龄办事通——面向社区养老服务的通知核验与办事指引**

项目处在设计阶段。本文约定首版要做什么、谁负责、怎样交接和验收。成员装机、华为云码道使用和上云流程见 [README_SETUP.md](README_SETUP.md)。

## 一次真实使用会是什么样

一位老人收到女儿转发的办事截图，想知道“这上面说要去社区，我明天需要去吗？”老人或家属用手机上传截图。系统识别事项，确认办理地区，在经过人工核对的官方资料中查找依据，再给出适合这位用户的下一步。老人可以听语音，家属可以查看引用原文，遇到需要线下核实的情况可以直接照着卡片提问。

首版解决三个问题：通知说的是哪件事，里面的要求是否适用于用户，以及用户接下来可以做什么。系统提供办事指引，资格审批和实际受理由经办部门负责。

## 试点范围

先打通一个区县的一项业务，再用同区县第二项养老服务验证同一套流程。高龄津贴是首个候选。具体区县、第二项业务和社区合作方由小组根据可获得的官方资料及访谈情况确定。首轮选材优先找得到发布机关、适用范围、办事原文和咨询渠道的事项。

老人和家属是主要使用者。社区工作人员可协助核对问题和试用。初期由成员③维护资料，用经过审核的表格导入数据库即可。试点若需要由社区持续维护，再做管理页面。

## 手机端流程

| 步骤 | 用户操作 | 系统行为 |
|---|---|---|
| 提交通知 | 拍照、选择相册截图或粘贴文字 | 识别正文并允许改正地名、日期等识别错误 |
| 补充条件 | 每次回答一个与办理有关的问题 | 区分通知发布地区和用户办理地区，只追问会影响结论的条件 |
| 查看办事卡 | 首屏看“建议下一步”，可点朗读 | 按需展示材料、办理渠道、时间和地点，关键建议带原文出处 |
| 家属协助 | 复制指引发给家属 | 一并复制适用地区和官方来源，便于家属复核 |

**核验逻辑**：截图提供待核对的说法。后端按事项和办理地找到候选条款，核对适用人群、生效时间及新旧条款的关系。发布日期较晚只能作为查找线索，条款替代关系需要原文支持。大模型可提取字段、把已有证据改写成口语；保留改变结论的限制条件，每个材料、日期和办理点都应能定位到出处。

| 核对结果 | 页面表现 |
|---|---|
| 条件齐全、证据一致 | 显示可执行的下一步，展开可见条款原文 |
| 用户信息不足 | 提出一个具体问题，补充后继续本次核对 |
| 地区超出试点、资料冲突或依据不足 | 说明具体缺口，生成一句可向社区询问的话；有经核实的联系方式时才展示 |
| 图片模糊或识别服务失败 | 保留已填信息，允许重新上传或粘贴文字 |

## 三人分工与交接

| 成员 | 负责的工作 | 第一轮交付 | 最终交付 |
|---|---|---|---|
| ① 前端与适老化交互 | React 手机页面、上传与纠错、逐步追问、结果卡、朗读及分享 | 用三组示例响应做出可点击的手机流程 | 接通真实后端；用手机验证文字大小、按钮、朗读及失败重试 |
| ② AI 与业务后端 | Express 接口、OCR 接入、字段提取、条款检索、条件判断和指引生成 | 接收文字及办理地区，返回有引用的结果或一个追问 | 接收真实截图，处理新旧文件、缺失条件和证据冲突 |
| ③ 资料、数据库与云端工程 | 收集核对官方材料、设计数据表、编写导入脚本、配置 RDS、部署应用、组织准确性评测 | 交付一份来源清楚的官方文件、若干可查询条款，以及对应的测试题和预期结果 | 可复现的建库与更新流程、可访问的华为云演示地址、测试记录及部署说明 |

③交给②的是有来源、有适用条件、可查询的条款。②负责决定该查哪条、哪些条件需要追问，并把结果交给①。①实现结果的呈现与交互。三人各自保存模块的开发记录、测试结果及展示素材，共同完成项目书和答辩。

## 第一版数据与接口约定

| 数据 | 由谁维护 | 最少包含 |
|---|---|---|
| 官方文件 | ③ | 文件编号、标题、发布机关、官网链接、发布日期、适用地区、最近核对日期 |
| 办事条款 | ③ | 条款编号、文件编号、事项、原文及所在段落、适用人群、生效／失效时间、办理动作、材料；有依据时记录替代了哪一条 |
| 测试案例 | ③草拟，②复核 | 输入、办理地区、用户已知条件、期望追问或指引、支持条款；资料未说明的字段留空 |

**①与②的接口草案**：上传截图调用 `POST /api/ocr`，返回可编辑的 `text`。核对调用 `POST /api/guide`，请求中带 `text`、办理地区 `region` 和已回答的条件 `answers`。追问后带上更新后的答案再次提交。返回的示意格式如下。

```json
{
  "status": "need_info",
  "question": { "key": "region", "text": "您想在哪个区县办理？" }
}
```

可给出指引时返回 `status: ready`、`nextStep`、`materials` 和 `sources`。每条关键建议关联条款编号，来源包含标题、原文、链接。需要人工确认时返回 `status: needs_review`、原因和可向社区提出的问题。网络或服务故障单独显示重试提示。①和②在写页面前各保存一份这三种响应的共同样例。

## 开发顺序与完成标准

1. **确定案例。** ③准备一项业务的资料和人工预期，②核对判断要用哪些字段，①画出老人从输入到获得下一步的页面。三人确认第一张结果卡的文字。
2. **跑通文字输入。** ①和②连通页面及接口，③完成本地资料导入。从手机页面输入通知，能拿到与原文对应的办事卡。
3. **接入真实服务。** ②接通 OCR，③把已核对的资料导入华为云 RDS，①实现识别纠错、语音朗读和转发文本。保留粘贴文字入口供识别失败时使用。
4. **上线和试用。** ③部署前后端，三人用另一部手机走完整流程。按同一接口补入第二项业务，记录哪些字段或页面需要调整。

验收至少覆盖完整本地通知、旧版条款、邻区通知、裁掉落款、文件冲突、图片无法识别。对每例记录实际输出、预期动作、引用是否支持结论。保留部分未用于调试的截图做最终测试。请试用者读或听完卡片后复述下一步，记录答对人数／试用人数与完成耗时。开发阶段演示数据须标为示例，正式演示使用已核对的资料。
